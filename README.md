# Stock Dip Analyzer Pro

A desktop market research workspace built with React, Vite, and Electron. Finviz is the primary stock screener and futures reference; Yahoo Finance supplies historical technical analysis and market context. Google News RSS supplies the Oil Watch headlines.

The Futures tab groups Finviz reference instruments across indices, rates, energy, metals, grains, softs, and currencies. It includes search, overview cards, actual source sparklines, and an instrument detail panel whose chart carries Finviz's own time labels and names its sampling interval (5-minute, hourly, daily, weekly or monthly). ## Data integrity

- Runtime views never substitute synthetic prices, scores, or news. A browser preview without Electron's source connection shows unavailable data.
- Retrieval time and source quote time are different fields. Unknown quote timestamps remain unknown; retrieving a response does not establish quote freshness. An Overview row's Retrieved time is when its Finviz screener page was retrieved (in the Photonics Basket, which reads Yahoo only, when its Yahoo chart was); its score breakdown shows the Yahoo quote time and when that chart was retrieved, which can be earlier than a screener row's own time when Settings → Data & sources → Chart cache reused the chart.
- Finviz's [FAQ](https://finviz.com/help/faq) specifies a **20-minute futures delay**, while its [current futures page](https://finviz.com/futures) says **15 minutes**. The app conservatively displays 20 minutes. This is delayed reference data, not a real-time exchange feed or a freshness guarantee.
- The Finviz futures feed does not supply a confirmed delivery contract or source quote timestamp. Native price units and Treasury decimal fractions are preserved; a universal dollar sign is not applied. A sparkline is drawn only when its last sample is within the session's high–low range (or 0.5 % of the price, if that is wider) of the quote; otherwise the chart is hidden with a note, because a thin market's 5-minute series can be a months-old history that ends far from the quote.
- Finviz US equity quotes are delayed one minute under its documented regular service. Yahoo delay metadata is shown when supplied; otherwise the delay is unknown. Yahoo's chart endpoint, which the app uses, supplies none. Displayed quote times include their timezone.
- Failed refreshes retain previous retrieved values only with stale/cached notices. While an Overview scan refreshes, each earlier row keeps its original score, quote time and retrieval time until it is rescored. Unknown and invalid values remain unavailable rather than becoming zero or a Hold rating, and a value that rounds to zero is never shown with a minus sign.
- Recovery scores are rule-based technical scores from a fixed one-month Yahoo history and its current source quote. They are not calibrated recovery probabilities or guarantees. Changing the detail chart range does not change the scoring period. The score's RSI is a simple 14-period RSI (Cutler's) over that month and is labelled "Simple RSI"; the RSI (14) Finviz and TradingView show is Wilder's and can differ.
- Technical alerts require a positive price, at least 15 daily closes, and a source quote whose own timestamp is between one minute ahead (clock skew) and five minutes old; a source that states a delay above zero is refused. Yahoo's chart endpoint states no delay, so the quote's age decides: during trading, a feed delayed by more than five minutes is refused, and from five minutes after a session's last trade until the next session trades, no technical alerts fire. Alerts come only from the Overview's scans, as each name is scored. A scan runs when you open the Overview or pick a sector or scan size there (unless a recent scan is reused), when you press Refresh quotes, and at each Settings → Scanner → Refresh interval while the Overview is the open desk; the interval is Off by default, and a scan already running finishes, and can still raise alerts, after you leave the Overview. An alert is raised when its condition turns true, stays silent while the condition holds, and re-arms when it clears or a new exchange-local day starts. When several conditions turn true together, one alert is raised: the first of breakout, breakdown, bullish and bearish that the Settings → Alerts switches and Minimum score allow. Minimum score applies to Bullish alerts only; breakout, breakdown and bearish alerts are raised whatever the score. The score rewards a dip and a bounce: a breakout, a price above the prior one-month closing high, has neither and scores 50 or less in practice, and breakdown and bearish warnings come from low-scoring setups. Messages describe observed technical conditions, not unmeasured trading flows.
- Excluded sectors (Settings → Scanner) narrow broad "any sector" scans only: the Overview's Any Sector scan and Discovery. A sector picked on the Overview is scanned in full. ETF rankings show the return period or dividend yield corresponding to their ranking criteria.
- When a Finviz page can no longer be read (a required column is unparseable, or Finviz ignores the requested page), or Yahoo fails for every name or for 16 names in a row, the Overview says so in words, and such a scan is never reused.

## Security

The app shows third-party web content (a TradingView chart in a sandboxed iframe, Finviz/Yahoo/Chartmill/StockCharts/Fidelity pages in embedded viewers), so the desktop shell is locked down accordingly:

- **Process model.** The renderer runs with `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`. `preload.cjs` exposes one function, `window.dipAnalyzer.invoke`, limited to `fetch-url`, `fetch-yahoo-chart` and `configure-network`. Page code cannot call Node, and the only Electron API it can reach besides that function is the `<webview>` element that hosts the research viewers. That bridge and the Content Security Policy below limit what code running in the app window itself, such as a compromised bundled library, can do, but they do not keep it from local files: a packaged build's window is a `file://` page, which Electron by default lets fetch other `file://` URLs, and such code can also drive a research viewer (see *Navigation and guests*).
- **Outbound requests.** `fetch-url` only accepts HTTPS URLs on the default port at `finviz.com`, `www.finviz.com` and `news.google.com`; `fetch-yahoo-chart` builds its own Yahoo URL after checking the symbol, range and interval. Anything else is refused in the main process before a request exists. For `fetch-url`, the main process follows redirects itself, at most five, holding every hop to the same allowlist, and keeps cookies in memory only, per host: each hop's cookies are filed under that hop's host and merged by name, a cookie set with a `Max-Age` of zero or less, or a past `Expires`, is deleted, and none is sent to another host. `fetch-yahoo-chart` requests only Yahoo's chart host (`query1.finance.yahoo.com`) and refuses every redirect: Yahoo answers that URL itself, so any redirect, whether to a consent page, another Yahoo host or the local network, fails the request with "Refused redirect to \<origin>." and is neither followed nor retried. Responses on both channels are read as a stream and refused past 15 MB, and an HTTP error answer from Yahoo is read for its explanation only up to 64 KB.
- **Navigation and guests.** The app window cannot navigate anywhere but the app, server redirects included, and a `file://` URL naming another host (a Windows UNC share) is refused. Every `<webview>` is attached without Node, isolated, sandboxed and without a preload, and may only start on the stock page's research sites, over HTTPS on the default port: `finviz.com`, `www.chartmill.com`, `stockcharts.com`, `digital.fidelity.com` and `finance.yahoo.com`. Once open, a viewer's own page can move, redirects included, only to HTTPS pages. That lock covers the navigations a viewer's page starts and server redirects, not loads the app window starts through the `<webview>` API, which can also read a viewer's page back: code running in the app window, such as a compromised bundled library, could load a `file://` or plain-HTTP page into a viewer and read it, and the lock would not stop it. The viewers share an in-memory session of their own, so cookies and sign-ins made there, such as a Fidelity login, never reach the app's profile on disk and are gone when the app quits: you sign in again in each run. Their media plays with sound only after a click or key press in that viewer, because Electron's default autoplay policy (`no-user-gesture-required`) lets an ad start playing sound by itself. Downloads a research site offers go through Electron's save dialog, so you confirm each file.
- **Links and popups.** `window.open` and `target="_blank"` never create app windows. The app's own links (news, StockFetcher, ETF Database) open http(s) URLs in the system browser. A link in a research viewer opens in the system browser only if it is HTTPS and comes within one second of a click, key press or tap in that viewer, once per gesture; scripted and ad popups are dropped. Known limits: a timer-driven popup that fires within that second can still open one HTTPS page, and since gestures come from the input events Electron reports for the viewer's page, a click inside a cross-site frame embedded in it may not count, so a new-window link in such a frame may do nothing.
- **Permissions.** Every permission request and check is denied (camera, microphone, location, notifications, fullscreen, clipboard reads and the rest), with one exception: the app window's own page may write text to the clipboard, which Settings → Backup → Copy needs. The TradingView frame and the research viewers get nothing. A server that asks any page for a TLS client certificate gets none: left to its default, Electron would send the first matching certificate from the system store without asking, so an ad frame in a research viewer could learn the name and organisation in a work or smart-card certificate. No provider or research site needs one; a site that requires one cannot be used in a viewer.
- **TradingView.** The chart is TradingView's own embed page in an iframe on `https://s.tradingview.com`, whose URL the app builds (`src/utils/tradingView.js`); TradingView's loader script never runs in the document that holds the desktop bridge. The iframe is sandboxed with `allow-scripts allow-same-origin` only (no popups, top navigation, downloads or forms) and gets no referrer, so links inside the chart do nothing.
- **Content Security Policy** (production builds, injected by `vite.config.js`): `default-src 'self'`; scripts, images, fonts, media, workers and connections from the app only; frames only from `https://s.tradingview.com`; `object-src 'none'`, `base-uri 'none'`, `form-action 'none'`. Inline styles remain allowed because documents parsed from Finviz markup fall under the policy.
- **What ships.** The installer contains Electron 45.2.1 (Node 24.22.1, Chromium 156), `main.cjs`, `preload.cjs` and the built `dist/`. Every npm package, React and Electron included, is a devDependency, so `npm audit --omit=dev` checks nothing and always reports 0; Electron updates arrive through Dependabot in a group of their own. A full `npm audit` reports 0 high and 20 moderate findings, all one advisory (GHSA-g3hv-75wg-m249, minimatch before 11.0.1, a denial of service on crafted glob patterns) reached only through electron-builder's and ESLint's dependency trees, which run at build and lint time and are not packaged. Do not run `npm audit fix --force`: its only fix is a downgrade to electron-builder 20.23.1.
- **No telemetry.** The app sends nothing about the user anywhere. Settings live in `localStorage` and contain no secrets.
- **Build output.** `npm run build` writes the installer and the unpacked app to `release/` (never into `dist/`, which is the renderer bundle that gets packed).
- **Installer signing.** Releases are unsigned until a code-signing certificate is configured as the release workflow's `CSC_LINK` / `CSC_KEY_PASSWORD` secrets; Windows SmartScreen will warn on an unsigned installer, and `SHA256SUMS.txt` is attached to every release for verification. The secrets are set only in the environment of the release job's electron-builder step, which is not isolation: the job's earlier steps (npm install scripts, the tests, lint and the renderer build) run on the same runner and can reach them and the job's write token. electron-builder also loads `electron-builder.env` from the working directory by itself, so `.gitignore` keeps that file, `*.pfx` and `*.p12` out of the repository; never commit signing material.

Data sources are public Finviz pages, Finviz's futures JSON endpoint, Yahoo Finance's chart endpoint and Google News RSS, used as a personal research tool with browser-like request headers. Their terms of use govern redistribution; review them before publishing the app to others.

## Install

Download the file for your system from the [latest release](https://github.com/Foxokiso/stock-dip-analyzer/releases/latest):

- **Ubuntu and Debian (x64):** `stock-dip-analyzer-<version>-amd64.deb`. In the folder you saved it to, run `sudo apt install ./stock-dip-analyzer-<version>-amd64.deb`, then open **DDS response** from the app menu or run `stock-dip-analyzer`. Installing a newer `.deb` the same way upgrades it; `sudo apt remove stock-dip-analyzer` removes it.
- **Other Linux (x64):** `stock-dip-analyzer-<version>-x86_64.AppImage`. Run `chmod +x` on it, then start it. It needs FUSE 2 (`sudo apt install libfuse2t64` on Ubuntu 24.04, `libfuse2` on 22.04), or start it with `--appimage-extract-and-run`. Where user namespaces are blocked, as on Ubuntu 24.04, the AppImage starts without Chromium's sandbox; use the `.deb` there.
- **Windows (x64):** `stock-dip-analyzer-<version>-x64-setup.exe`. The installer is unsigned, so SmartScreen warns on its first run; compare its SHA-256 with `SHA256SUMS.txt` before running it.

Settings are kept per install (a packaged app and `npm start` keep separate ones); Settings → Backup exports and imports them.

## Run locally

Requires Node.js 22.12 or later (supported by this Vite version).

```bash
npm ci
npm start
```

`npm start` runs Vite, starts Electron once Vite answers on `127.0.0.1:5174`, and stops the two together. Quitting the app stops Vite. Ctrl+C, closing the terminal, or SIGTERM to `npm start` (what an editor's Stop button or `kill` sends) stops both. If either one exits on its own, the other is stopped too. Force-killing npm's own process alone (`kill -9`, or ending only that process in Task Manager) can still leave them running. Arguments after `npm start --` go to Electron. `npm ci` does not download Electron itself: the first `npm start` (or `npm run electron`, or `npm run test:live` without `ELECTRON_EXE`) downloads the Electron binary matching the installed `electron` package from Electron's GitHub releases and checks it against the SHA-256 sums that package ships; set `ELECTRON_MIRROR` to download from a mirror instead. `npm run dev` provides a browser layout preview; market data requires Electron. Both serve the renderer on `127.0.0.1:5174` with `--strictPort`: if that port is taken, Vite exits instead of moving to another port, because `npm run electron` waits on 5174 and the main process trusts only that address in development. `npm start` refuses to start at all while something already answers there, such as an earlier `npm run dev`, and says so. Existing refresh settings and alternate themes are retained.

On Ubuntu 23.10 and later, AppArmor blocks the user namespaces Chromium's sandbox uses, and the Electron binary that `npm start` downloads is not set up to sandbox without them, so it stops with "The SUID sandbox helper binary was found, but is not configured correctly". Install the `.deb` instead, or make the downloaded helper setuid root (again after every fresh `npm ci`):

```bash
sudo chown root:root node_modules/electron/dist/chrome-sandbox
sudo chmod 4755 node_modules/electron/dist/chrome-sandbox
```

the stub and the page watcher they share are in `scripts/ui-harness.mjs`. `verify-ui.mjs` checks every desk and a not-found route at 1440 and 390 px without the desktop bridge (the desk's heading, one `h1` in `<main>`, its own unavailable notices, no price, the window title, no sideways scroll); futures filtering, decimal precision and retained cached quotes; the Appearance and Data settings, the number fields and Backup → Copy; the stock page on recorded data (52-week strip, statistics, publishers, tones, price axis, independent sections, symbol switch and the refresh schedule that restarts with it, the sandboxed TradingView frame); keyboard links, unclipped source lines and sector settling on the Overview; that a desk opened from a scrolled page opens at the top with its heading focused, and where focus goes after a desk error and when Seizure Mode ends, whose controls stay clear of the alert history button at 320 px; selected states and focus rings under forced colours; recovery from a failed stock-page chunk, whether the browser fetches it again or the error panel's Reload is needed; refused storage; and the legacy `window.require('electron')` bridge that `src/utils/bridge.js` keeps for these scripts. `verify-alerts.mjs` checks the alert sound and its limits, the history drawer and where focus goes as it opens and closes, that the history button never hides a focused control, that the alert layer stays in view in Alien Fractal, and the alert rules end to end, with the browser clock set two and six minutes after a recorded close: breakdowns, the bearish trend raised instead when Breakdown alerts are off, a breakout raised by a scan at the default Minimum score, the quote and retrieval times a score shows after a refresh that reused its chart, and an Overview in a hidden window that keeps scanning while an alert type is enabled and pauses when none is. Screenshots are written to the ignored `artifacts/` directory.

Two checks use live data and are run by hand:

- `npm run test:finviz` fetches every Finviz screener view the desks request, the stock page's quote page and the futures API, and runs the app's parsers on them, without Electron. It exits 1 when a view returns no rows, starts at the wrong row or ignores its sector filter or signal, when the quote page loses a statistic, its 52-week bounds or its headline publishers, when the futures API returns no priced instrument, or when a screener view, the quote page or the futures API is redirected.
- `npm run test:live` launches the app in Electron through Playwright (starting the dev server itself, or driving a packaged build named by `ELECTRON_EXE`), walks every route twice with live data and times what a user feels. It needs a display (on Linux without one, run it under `xvfb-run -a`) and, without `ELECTRON_EXE`, the Electron binary (see *Run locally*). In that dev mode it runs Vite with Node itself on `127.0.0.1:5174` and stops it when the run ends, even one that failed; it refuses to start while something already answers there (stop `npm run dev` first), and fails at once, with Vite's own message, when its server exits before answering. It exits 1 and lists every failed check: renderer isolation, a research viewer that reaches Node or is outside the private research session (or no viewer to probe), the bridge surface, the TradingView sandbox, the CSP of a packaged build, page errors from the app, CSP violations (or violations it could not read), refused requests, Backup → Copy, or a desk without live data (`LIVE_DATA_OPTIONAL=1` reports the last as warnings). Page errors from a third-party frame, such as TradingView's chart, and provider redirects the main process refused, such as Yahoo sending a chart request to a consent page, are listed as warnings. It presses Copy once, so the system clipboard ends up holding the settings export. Screenshots and `report.json` go to `artifacts/live/`.

CI has five workflows in `.github/workflows/`. `ci.yml` runs the tests, lint, the renderer build and the browser regressions on Linux for every pull request and every push to `master`. It runs the unit tests a second time with `TZ=America/New_York` and `LANG=de_DE.UTF-8`, after checking that Node really resolved that zone and locale (an `LC_ALL` would override `LANG`), and the browser regressions a second time against `vite preview` of the production build on `127.0.0.1:4174`. `native-core.yml` runs the C++ parity suites on Ubuntu and Windows, plus a sanitizer build, for pushes to `master` and pull requests that touch the core or the code it mirrors. `windows-installer.yml` runs the tests, lint and browser regressions on Windows and builds an unsigned NSIS installer, for pull requests and pushes to `master`. `linux-packages.yml` builds the `.deb` and the AppImage for pull requests and pushes to `master`, checks what they contain, installs the `.deb` with apt on Ubuntu 24.04 and starts the installed app, which must open its window within 60 seconds. `release.yml` turns a `v*` tag into a GitHub Release: a small job checks the tag against the version in `package.json` while `ci.yml` and `native-core.yml` run as reusable workflows with the release workflow's read-only token and no secrets; only after all three have passed on the tagged commit are the Windows installer and, through `linux-packages.yml`, the Linux packages built, with read-only tokens, and a separate publish job, the only one with write access, creates the release with every file and their SHA-256 sums. Dependabot proposes npm and GitHub Actions updates weekly.

`npm run build` also invokes electron-builder to create a platform installer. Native packaging requires the target platform's build dependencies; the renderer build alone does not verify an installer.

## Using Antigravity

Google Antigravity reads this repository's agent setup on its own: `AGENTS.md` on every turn, the three rules in `.agents/rules/` when the agent works on their files (the C++ mirror, the Electron security surface, the CI workflows), and the five skills in `.agents/skills/` when a task matches them.

1. Pull the latest `master` and open the repository's root folder (the one with `package.json`) as the workspace, or add it to a project in the Antigravity app. Antigravity looks for these files in the open folder and its parent folders up to the repository root, not in subfolders.
2. Check that it found them. In the Antigravity CLI (`agy`), `/context` lists the loaded rule files and how many tokens the rules and skills use; after a `git pull` in a session that is already running, `/skills reload` (or a new conversation) picks up the skills. In the IDE, the skills (`run-app`, `verify-changes`, `fix-finviz-parsing`, `build-linux-package`, `cut-release`) are under the Customizations menu.
3. Ask in plain words: "run the app", "verify my change", "the Overview shows no rows, fix the Finviz parsing", "build the Linux package". In the Antigravity app and CLI a skill also runs as a slash command, such as `/run-app`.
4. To be asked less often, allow the safe commands for this project. In the CLI, `/permissions` opens the Permissions Manager; under the Project scope add `command(npm test)`, `command(npm run verify)` and `command(npm run lint)`. In the app, a project's permissions are under Settings → Projects. Leave `npm start` and anything with `sudo` to ask.

## Source limits

Public providers can be unavailable, delayed, rate limited, or change their response schemas. Network requests have bounded timeouts (Settings → Data & sources → Request timeout, 12 s by default), and failures are shown in the interface in the provider's words: its HTTP status, Yahoo's own explanation, or the network error. Live prices with exchange entitlements require an authorized feed or broker connection; Finviz's built-in futures delay cannot be removed by faster polling.
